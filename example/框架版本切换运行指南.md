# RN 框架版本切换运行指南

本工程（example）支持在 **RN 0.72 / 0.77 / 0.82 / 0.84** 四个框架版本间切换，用于验证 `BidirectionalFlatList` 在各 RNOH 框架版本下的表现。切换由脚本 `example/switch-rn.js` 完成，它会改写依赖配置、安装依赖并重新生成 bundle。

## 一、环境要求

| 依赖 | 要求 |
| --- | --- |
| Node | ≥ 20 |
| DevEco Studio | 6.0.1 及以上（含 HarmonyOS 6.0.1 SDK） |
| hdc | 已配置到环境变量（真机调试） |
| RNOH_C_API_ARCH | 系统环境变量设为 `1`（C-API 架构，首次配置后需重启终端/IDE） |

## 二、切换版本（核心命令）

在 `example` 目录下执行：

```bash
node switch-rn.js <版本号>      # 版本号：0.72 | 0.77 | 0.82 | 0.84
```

例如切换到 0.77：

```bash
node switch-rn.js 0.77
```

脚本会自动完成：

1. 覆盖 `package.json`、`babel.config.js` 及 harmony 侧配置（oh-package.json5、ets/cpp 包注册、CMakeLists.txt）；
2. 执行 `npm install`（耗时数分钟）；
3. 探测当前框架包内实际的 har 文件名并回填 oh-package.json5；
4. 删除旧 ohpm 锁文件、清理 metro 缓存，执行 `npm run dev` 重新生成 `bundle.harmony.js`。

辅助命令：

```bash
node switch-rn.js --list       # 查看支持的版本及依赖配套
node switch-rn.js --current    # 查看当前框架版本
node switch-rn.js 0.77 --no-install   # 只改配置不装依赖（一般不用）
node switch-rn.js 0.77 --no-bundle    # 切换后不生成 bundle
```

## 三、切换后构建运行

脚本执行成功后，还需在 DevEco Studio 中重新构建原生工程：

1. 用 DevEco Studio 打开 `example/harmony` 工程；
2. 等待右下角 **Sync / Install** 完成（ohpm 重新解析 har 依赖，har 较大、耗时较长，务必等 Sync 全部结束）；
3. **Build > Build Hap(s)/APP(s) > Build Hap(s)** 重新构建（切换版本后请勿用增量缓存，如遇异常先 Clean 再构建）；
4. 运行到真机/模拟器，按测试用例验证。

## 四、版本配套矩阵

reanimated 配套以 [rntpc_react-native-reanimated](https://gitcode.com/CPF-RN/rntpc_react-native-reanimated) 各分支文档为准：

| 框架版本 | react-native | react | RNOH JS 包（harmony） | reanimated 双端 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 0.72 | 0.72.5 | 18.2.0 | 0.72.139 | 3.6.0 / @ohos ~3.6.5 | 已验证基线 |
| 0.77 | 0.77.1 | 18.3.1 | 0.77.71（0.77-stable） | 3.18.0 / @ohos ~3.18.1 | reanimated 手动注册 |
| 0.82 | 0.82.1 | 19.1.1 | 0.82.30（0.82-stable） | 4.2.1 / @ohos 4.0.2，worklets 0.7.1 / @ohos 1.0.1 | reanimated+worklets 手动注册 |
| 0.84 | 0.84.1 | 19.2.3 | 0.84.4（0.84-rc） | 同 0.82 | 见下方已知限制 |

> 0.82 起 reanimated 4.x 的 worklet 能力独立成库，babel 插件从 `react-native-reanimated/plugin` 换成 `react-native-worklets/plugin`，harmony 侧需同时引入 worklets 的 har 与 C++ 目标——以上差异均由切换脚本自动处理。

## 五、已知限制

1. **0.84 使用 br_rnoh0.84 分支的 beta 配套（2026-11-02 已跑通）**：npm 上官方 `@react-native-ohos/react-native-reanimated ~4.1.0` / `react-native-worklets ~1.1.0` 尚未发布（br_rnoh0.84 分支标注"进行中"），0.82 线的 4.0.2 / 1.0.1 与 0.84.4 har **硬性不兼容**（`hermes/inspector/RuntimeAdapter.h` 已被 0.84.4 移除，worklets 1.0.1 编译必挂）。当前方案：从 gitcode `CPF-RN/rntpc_react-native-reanimated` br_rnoh0.84 分支源码本地 `npm pack` 出 `4.1.0-beta.1` / `1.1.0-beta.1`，存于 `example/local-ohos-packages/`，模板以 `file:` 引用；JS 侧 worklets 需升到 `0.11.4`（beta 包 peer 指定）。另有三个 0.84 专属适配（均已固化在 `rn-versions/0.84` 模板）：
   - `CMakeLists.txt` 加 `add_compile_definitions(RN_ENABLE_DEBUG_STRING_CONVERTIBLE=1)`：否则 `BackgroundImage.h` 的无条件内联 `toString` 引用被 `#if RN_DEBUG_STRING_CONVERTIBLE` 编空的 `LinearGradient/RadialGradient::toString`，链接 `libreactnative.so` 报 undefined symbol（我们全局 `-DNDEBUG` 会触发）；
   - `PackageProvider.cpp` / `RNPackagesFactory.ets` 改为**纯 autolink**（beta 包恢复 autolink，CLI 在 npm run dev 时生成含注册的 factory；手动再注册会双重包含无 guard 的头文件导致重定义）；
   - worklets/reanimated 目标仍按手动 `add_subdirectory` 接入（官方 example 同款）。
   
   官方 4.1.0/1.1.0 正式发布后：把 `rn-versions/0.84/package.json` 中两个 `file:./local-ohos-packages/...` 换回 npm 版本号、重切一次即可，其余适配不变。
2. 0.84 的 RNOH 框架包当前为 `0.84-rc` 线（npm 上 0.84 暂无 stable tag），如遇问题可回退 0.82 验证。

## 六、常见问题

| 现象 | 处理 |
| --- | --- |
| BuildNativeWithCmake 报 add_subdirectory 源目录不存在 / set_target_properties 找不到 `rnoh` 目标 | 0.77+ 必须引用**全量 `react_native_openharmony.har`**（157MB，含 `src/main/cpp`）；`release.har` 只有 ets 无 C++ 源码（0.72 例外：其 release.har 带头文件+预编译库）。检查 `harmony` 与 `entry` 两级 oh-package.json5 均指向全量 har，且工程级 `dependencies` 显式声明了 `@rnoh/react-native-openharmony`（确保装到 `harmony/oh_modules/@rnoh`，CMakeLists 从该路径取源码）。改完后删两级 oh-package-lock.json5 与 `entry/oh_modules/@rnoh` 再 Sync |
| ProcessLibs 报 `Duplicated files`（如 libhermes.so 同时出现在 har 的 `libs/arm64-v8a/` 与 `entry/build/.../obj/arm64-v8a/`） | 跨版本切换后的旧构建产物残留（0.72 预编译 so 与 0.77+ 源码编译 so 同名冲突）。删除 `harmony/entry/build` 与 `harmony/entry/.cxx` 后重新 Build（切换脚本已自动清理，手动改配置时需自查） |
| `'react-native' 不是内部或外部命令` | 在 example 下重新执行 `npm install` |
| DevEco Sync 卡住 / ohpm 报找不到 har | 确认 Sync 与 Install 全部结束再构建；仍异常则删除 `harmony/oh_modules` 与 `.hvigor` 缓存后重新 Sync |
| 构建报 C++ 目标冲突或 so 拷贝 ENOENT | Build > Clean Project 后重新 Build Hap(s) |
| 运行后白屏/报 bundle 加载失败 | 确认切换后执行过 `npm run dev`（`harmony/entry/src/main/resources/rawfile/bundle.harmony.js` 的修改时间应为切换之后） |
| 想确认当前版本 | `node switch-rn.js --current` |

## 七、脚本维护说明（开发者）

各版本的工程配置模板存放在 `example/rn-versions/<版本>/` 下（package.json、babel.config.js、harmony 侧全部需差异化的文件），脚本只做"覆盖模板 + npm install + har 文件名回填"。升级某个版本的配套依赖时，直接修改对应模板文件即可，无需改脚本逻辑。
